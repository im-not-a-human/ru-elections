# Поимённые голосования депутатов — дизайн

**Дата:** 2026-05-07
**Контекст:** в `LAWS[]` хранится только сводка по фракциям (`za`/`against`/...). Нужна возможность увидеть, как проголосовал каждый депутат лично.

## Цель

Из модала закона на главной странице открыть полноэкранную панель с таблицей депутатов в колонках по фракциям. Цвет плашки депутата = его голос. «Диссиденты» (голос ≠ мажоритарной позиции фракции) — наверху каждой колонки.

## Решения, принятые в брейнсторминге

1. **UX placement** — полноэкранная панель из существующего модала (кнопка «Посмотреть поимённо»).
2. **Сортировка в колонке** — сначала «отличающиеся» (по группам: против / воздержался / не голосовал / за), потом алфавит внутри группы.
3. **Составные законы** — вкладки внутри панели:
   - Пакет Клишаса (id `606595-7`) → 2 вкладки: «Фейки» (606593-7) / «Неуважение» (606594-7)
   - `fkz-2022-territories` → 4 вкладки: ДНР / ЛНР / Запорожье / Херсон
4. **Хранение данных** — один JSON на `LAWS.id` (см. ниже).
5. **Источники в UI** — ссылки на публичные страницы `vote.duma.gov.ru` и `sozd.duma.gov.ru` (без app-token).
6. **API-токен** — только локально через переменную окружения, в исходники не коммитим.

## Архитектура

### Поток данных
```
api.duma.gov.ru (через VPS-2 / SOCKS5)
   └─ voteSearch.xml?bill_number=…  →  vote_id
   └─ vote/{voteId}.xml             →  XML с <resultsByDeputy>
        ↓
tools/fetch-votes.py
   ├─ читает vote-mapping (LAWS.id → [voteId])
   ├─ скачивает в research/compromat/05-evidence/duma-api/votes/  (там уже 28 файлов)
   └─ пишет компактный assets/data/votes/{lawId}.json
        ↓
front-end (lazy fetch по клику в law-modal)
   └─ deputy-panel.js рендерит панель
```

### Компоненты

| Файл | Роль |
|---|---|
| `assets/js/data/vote-mapping.js` | `VOTE_MAPPING = { lawId: [{voteId, tabLabel?}], … }` |
| `assets/data/votes/{lawId}.json` | компактные данные (см. формат ниже) |
| `assets/js/components/deputy-panel.js` | `window.openDeputyPanel(lawId)`, рендер DOM, focus trap, ESC |
| `assets/css/components.css` (доп. секция) | стили `.deputy-panel`, `.deputy-col`, `.deputy-row`, `.deputy-tab` |
| `assets/js/components/law-modal.js` (правка) | кнопка «Посмотреть поимённо» |
| `tools/fetch-votes.py` | скачать недостающее + сгенерировать JSON для фронта |
| `index.html` | `<script>` теги для двух новых файлов |
| `.gitignore` | добавить `.env` |

### Формат `assets/data/votes/{lawId}.json`
```json
{
  "lawId": "608767-7",
  "ballots": [{
    "voteId": "107479",
    "tabLabel": null,
    "billId": "608767-7",
    "date": "2019-04-16",
    "subject": "(3-е чтение) О суверенном Рунете",
    "voteUrl": "https://vote.duma.gov.ru/vote/107479",
    "sozdUrl": "https://sozd.duma.gov.ru/bill/608767-7",
    "totals": { "for": 307, "against": 68, "abstain": 0, "absent": 75 },
    "factions": [
      { "code": "ER",   "majority": "for",     "for": 302, "against": 0,  "abstain": 0, "absent": 37 },
      { "code": "KPRF", "majority": "against", "for": 0,   "against": 33, "abstain": 0, "absent": 10 }
    ],
    "deputies": [
      { "name": "Луговой А.К.",     "factionCode": "LDPR", "result": "for" },
      { "name": "Жириновский В.В.", "factionCode": "LDPR", "result": "against" }
    ]
  }]
}
```

`result` ∈ `for | against | abstain | absent`.
Имена сжимаем до «Фамилия И.О.» — экономит ~30% места и удобнее для отображения.

```
┌──────────────────────────────────────────────────────────────────┐
│  ← Закон                                                      ✕  │
│  Суверенный Рунет        16.04.2019 · 307/68/0 · ФЗ № 90-ФЗ      │
│  Источники: vote.duma.gov.ru · sozd.duma.gov.ru                  │
│  [Легенда: ■ за  ■ против  ■ воздерж  ▢ не голосовал]            │
├──────────────────────────────────────────────────────────────────┤
│  ЕР 325         КПРФ 57     ЛДПР 23     СРЗП 28     НЛ 15        │
│  ───────        ───────     ───────     ───────     ───────      │
│  ▼ диссиденты   ▼ диссид.   ▼ диссид.   ▼ диссид.   (нет)        │
│  ░░ Попов Е.    (никто)     ▌ Луговой   ▌ Иванов    …            │
│  ▼ за           ▼ против    ▼ против    ▼ против                  │
│  █ Аксаков А.   █ Зюганов   █ Слуцкий   …                         │
│  …              …           …                                     │
└──────────────────────────────────────────────────────────────────┘
```

- Заголовок колонки = название фракции + сводка `for/against/abstain/absent`, граница сверху — цветом фракции (как в `law-modal`).
- Ряд депутата: 2-3px цветная полоска слева (цвет голоса) + фамилия + (опционально) chip-метка для диссидентов («против фракции»).
- Внутри колонки — секции по голосу (collapsible accordion **не нужен**, просто заголовок-разделитель).
- Колонка скроллится независимо.
- Mobile (<768px): вместо 5 колонок — chip-tabs фракций сверху, одна активная колонка ниже.
- Tabs составных законов: над колонками, переключают `ballots[]`.

### Цветовая палитра голосов (новые токены)

```css
--vote-for:     #2A8B3E;  /* зелёный */
--vote-against: #C0392B;  /* красный */
--vote-abstain: #D89B2D;  /* охра */
--vote-absent:  #9B958B;  /* серый */
```

Эти цвета — фон chip-метки и левый бордер строки депутата. Не путать с цветами фракций (используются для границ колонок и заголовков).

### Доступность и нюансы
- Focus trap внутри панели, ESC закрывает.
- `prefers-reduced-motion`: без slide-in.
- `role="dialog" aria-modal="true" aria-labelledby="deputy-panel-title"`.
- На no-JS — кнопка «поимённо» просто не появляется (как и существующая модалка).
- Источники в самой панели — обязательны: `vote.duma.gov.ru` (поимённый раздел) + `sozd.duma.gov.ru` (карточка билла) + явная атрибуция «Данные: API Государственной Думы».

### Скрипт `tools/fetch-votes.py`

- Читает `DUMA_APP_TOKEN` и опционально `HTTPS_PROXY` / `DUMA_PROXY` из `.env` или окружения.
- Источник vote-mapping — `assets/js/data/vote-mapping.js` (парсим простым regex или дублируем mapping в Python — для надёжности дублируем как `VOTE_MAPPING` константу в скрипте).
- Скачивает недостающие XML в `research/compromat/05-evidence/duma-api/votes/{shortname}.xml`. Имена коротких слугов берём из существующего `parse_votes.py:VOTES_META`, для новых — генерим из bill_id.
- Парсит и пишет `assets/data/votes/{lawId}.json` для всех LAWS.id из mapping.
- Идемпотентен: skip download если файл существует.
- НЕ хранит токен в выходных файлах.

### Что **не** делаем (YAGNI)
- Поиск по фамилии в панели — пока не нужно, сортировка решает.
- Фотографии депутатов — приятный bonus, но раздувает данные. Пропускаем.
- Связь имени депутата с её карточкой/декларацией — отдельная история.
- Кеш скачивания на CDN. Файлы статические, GH Pages кеширует.

## Покрытие законов

В `LAWS[]` ~25 записей. У ~13 из них уже есть скачанный XML в `research/compromat/05-evidence/duma-api/votes/`. Для остальных нужен fetch. Полный mapping `LAWS.id → vote_id` собирается на этапе плана реализации (через `voteSearch.xml?bill_number=…`).

## Безопасность

- `.env` в `.gitignore` (добавим).
- В коммите ни токена, ни URL-ов с токеном.
- В UI ссылки только на публичные `vote.duma.gov.ru` / `sozd.duma.gov.ru`.
