### 🔴 `8 из 15` сейчас расшифровано неверно

**Где:** `vybory.html:363`, `assets/js/data/elections.js:108`, частично `assets/js/data/elections.js:59-109`

Сама формула `8 из 15` подтверждается «Медиазоной»: в восьми московских округах оппозиционные кандидаты лидировали до публикации ДЭГ и проиграли после неё. Но текущая расшифровка неверна: сайт пишет «семеро КПРФ: Рашкин, Лобанов, Парфёнов, Удальцова, Обухов, Гребенник, Таранцов».

По данным «Медиазоны» эти восемь: Рашкин, Лобанов, Брюханова, Митрохин, Обухов, Парфёнов, Гребенник, Удальцова. То есть **6 КПРФ + Брюханова + Митрохин**, а не 7 КПРФ + Митрохин. Таранцов по raw-data не лидировал по бумаге: Романенко `34 927`, Таранцов `34 274`.

Дополнительно таблица `DEG_FLIPS_2021` показывает только 6 строк из 8: нет №205 Преображенского / Обухова и №206 Тушинского / Гребенника. Если текст утверждает «8 из 15», таблица должна либо показывать все 8, либо явно называться «ключевые примеры».

**Источники:** [Медиазона](https://zona.media/chronicle/electrovote), [raw-data](https://raw.githubusercontent.com/mediazona/data-el2021-deg-moscow-singles/main/deg.json)

### 🟡 Кунцевский №197: числа верные, но note искажает смысл переворота

**Где:** `assets/js/data/elections.js:64-67`

`paper: 46 129 / 34 305` и `deg: 26 676 / 46 589` точны по raw-data. Но note говорит: «После ДЭГ Попов получил +12 тыс. сверху и победил». Это не величина переворота.

Корректнее:

- бумажный отрыв Лобанова: `46 129 - 34 305 = 11 824`;
- преимущество Попова в ДЭГ-слое: `46 589 - 26 676 = 19 913`;

Фраза `+12 тыс.` описывает только разницу между бумажным и ДЭГ-результатом самого Попова, а не механизм переворота.

## 2. Калькулятор и heatmap

### 🔴 One-party edge отдаёт ЕР все 225 списочных мест

**Где:** `assets/js/charts/calculator.js:9-28`, `assets/js/charts/calculator.js:54-64`

Воспроизведение: оставить ЕР `49,82%`, выставить КПРФ/ЛДПР/СРЗП/НЛ в `0`. Браузерный результат: `list=225`, `total=425`, warning отсутствует.

Причина: `getAdmittedLists` фильтрует только `share > 0`. Если положительная партия одна, она возвращается как единственная допущенная, хотя условия ст. 88 (`минимум 2 списка` и `сумма > 50%`) не выполнены.

Что должно быть: сценарий нужно помечать как невалидный/недоопределённый или вводить явный residual bucket «прочие партии/ниже барьера». Молчаливо отдавать все 225 мест партии с 49,82% нельзя: это ломает доверие к интерактиву.

**Уровень:** 🔴

## 3. UX-регрессии

### 🔴 На iPhone SE есть горизонтальный overflow

**Где:** `index.html:36-39`, `vybory.html:36-39`, `assets/css/layout.css:40-48`, `assets/css/layout.css:51-72`

На 320×568 `.page-toggle` имеет ширину около `298px` и начинается после brand mark (`x=64`), поэтому правый край уходит до `x=362`. Документ становится шире viewport: `index.html` примерно `377px`, `vybory.html` примерно `628px`.

На скриншоте nav обрезает «Математика выборов». Это критично для первого экрана: главный cross-page affordance выглядит сломанным.

**Уровень:** 🔴

### 🔴 DEG-таблица всё ещё расширяет body на мобильном

**Где:** `vybory.html:366-378`, `assets/css/elections.css:563-574`

CSS стакает `#degBody tr/td`, но `thead` и сама таблица продолжают иметь min-content ширину около `604px`. На 320px это даёт body width `628px`.

Нужно на `<720px>` скрывать `thead`, делать `table/tbody` block, а `td` подписывать через `data-label`, либо полностью рендерить мобильную карточную версию.

**Уровень:** 🔴

### 🟡 `prefers-reduced-motion` гасит ping, но tooltip не остаётся видимым

**Где:** `assets/css/base.css:57-63`, `assets/css/layout.css:84-110`, `assets/js/lib/page-toggle-ping.js:18-25`

В reduced-motion `.is-pinging` всё равно добавляется, но глобальное правило превращает анимацию tooltip в `0.01ms`; псевдоэлемент заканчивает на `opacity:0`. Итог: ни нормального статичного tooltip, ни явного отключения onboarding-сигнала.

Лучше: в JS не запускать ping при `matchMedia('(prefers-reduced-motion: reduce)')`, либо в CSS дать reduced-motion статичный `outline` + `::after { opacity: 1; animation: none; }` на 4 секунды через JS class.

## 4. A11y

### 🟡 `role=tablist` не подходит для межстраничной навигации

**Где:** `index.html:36-39`, `vybory.html:36-39`

Ссылки ведут на разные HTML-страницы. Это не tabs pattern: нет `tabpanel`, нет `aria-selected`, нет ожидаемой клавиатурной модели вкладок. WAI-ARIA APG описывает tabs как переключение связанных panel внутри одного интерфейса.

Правильнее: обычный nav/links + `aria-current="page"` на текущей ссылке. Можно добавить `aria-label="Основные разделы"` на контейнер.

**Источник:** [W3C APG Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)

**Уровень:** 🟡

### 🟡 Spoiler cover остаётся в accessibility tree после раскрытия

**Где:** `assets/js/lib/spoiler.js:11-15`, `assets/css/elections.css:249-305`

После reveal cover получает `tabIndex=-1`, `opacity:0`, `pointer-events:none`, но остаётся `<button>` в DOM и accessibility tree. Для клавиатуры это уже почти ок, но виртуальный курсор скринридера всё ещё может дойти до невидимой кнопки.

Решение: после transition ставить `hidden`, `inert` и/или `aria-hidden="true"` на cover; content уже переводится в `aria-hidden="false"`.

**Уровень:** 🟡

### 🟡 Modal/intro не изолируют фон для assistive tech

**Где:** `index.html:318-321`, `assets/js/lib/modal.js:27-40`, `assets/js/lib/intro.js:23-40`

Фокус trap есть, но фон не получает `inert`/`aria-hidden`. Кроме того, `aria-labelledby="modalContent"` на modal overlay указывает на весь динамический контент, а не на конкретный заголовок модалки.

До публикации не блокер, но для аккуратного a11y лучше добавить общий helper: при открытии диалога inert-ить `main/nav/footer`, при закрытии восстанавливать; `aria-labelledby` указывать на id заголовка внутри модалки.

**Уровень:** 🟡

# II. UX И МЕДИА — ТОП-10 РЕКОМЕНДАЦИЙ

## 1. Починить мобильный nav как первое впечатление

- **Что:** на `<=520px` сделать page-toggle отдельной строкой или полноценной шириной внутри nav; убрать `role=tablist`; не допускать body overflow.
- **Зачем:** сейчас первый экран на iPhone SE визуально ломается: «Математика выборов» обрезана. Для соцсетевого трафика это потеря доверия до чтения текста.
- **Как реализовать:** `nav-row` на mobile: `grid-template-columns: auto 1fr`, brand mark слева, toggle занимает `grid-column: 1 / -1` или `width:100%; max-width:280px; justify-self:center`; уменьшить padding до `6px 10px`. Объём: **S**.
- **Эффект / усилие:** 5 / 2.

## 2. Вынести главный stat above the fold на мобильном

- **Что:** на главной сразу под H1 показать компактный ударный факт `2 из 18` или `407/450`; на `vybory` — `49,82% → 72%` до длинного deck.
- **Зачем:** сейчас первый stat на главной начинается примерно с `y=693`, на `vybory` — около `y=1119`. В первые 3 секунды мобильный читатель видит только заголовок и длинный абзац, но не «удар».
- **Как реализовать:** mobile-only `.hero-kicker-stat` / `.elections-kicker-stat`: крупное число, короткая подпись, без карточки. Большую stats-strip оставить ниже. Объём: **S**.
- **Эффект / усилие:** 5 / 2.

## 3. Добавить OG/Twitter preview и статичную share-картинку

- **Что:** `og:title`, `og:description`, `og:image`, `twitter:card`; картинка 1200×630 для каждой страницы.
- **Зачем:** Telegram, X, Facebook и СМИ будут показывать сейчас почти пустой/случайный preview. Для медиа-публикации OG-картинка важнее многих микроанимаций.
- **Как реализовать:** статичный SVG/PNG в стиле сайта: бумажный фон, чёрный/красный, главный тезис. Для `vybory`: `49,82% → 72%` и подпись `как голоса становятся большинством`; для главной: `2/18` и `голосование без выбора`. Объём: **S-M**.
- **Эффект / усилие:** 5 / 2.

## 4. Сделать 3-5 «скриншотных» callout-блоков

- **Что:** привести ключевые числа к одинаковому формату share-card: крупное число, одна строка тезиса, маленькая строка источника.
- **Зачем:** скриншот должен работать без контекста страницы. Сейчас сильные числа есть, но часть из них растворена в абзацах/таблицах.
- **Как реализовать:** выделить: `2/18`, `49,82% → 72%`, `198/225`, `8/15`, `14 млн / 22 млн`, `152 ₽/голос`. Добавить `id` и `copy link/share` только к этим блокам. Объём: **S**.
- **Эффект / усилие:** 5 / 2.

## 5. Добавить тонкий progress-bar под nav

- **Что:** 2px reading progress под sticky nav.
- **Зачем:** страницы длинные; progress-bar даёт ощущение движения и снижает тревогу «сколько ещё». Для клипового чтения это дешёвый выигрыш.
- **Как реализовать:** vanilla JS `scroll` с `requestAnimationFrame`; CSS transform scaleX; respect reduced-motion без transition. Объём: **XS-S**.
- **Эффект / усилие:** 4 / 1.

## 6. Переделать «реальный пример» в scroll-step, не параллакс

- **Что:** 4-шаговый расчёт в `vybory.html:222-256` раскрывать по шагам при скролле, с подсветкой текущей формулы.
- **Зачем:** это идеальный scrollytelling-узел: читатель буквально видит, как `500 000 → 200 000 → 70 000 → 14%`.
- **Как реализовать:** `IntersectionObserver` на `.step`, active class, слева sticky mini-total на desktop; на mobile обычное последовательное раскрытие. Без тяжёлого parallax. Объём: **M**.
- **Эффект / усилие:** 4 / 3.

## 7. Дать ДЭГ-разделу мобильную карточную драматургию

- **Что:** после исправления 8 округов показать их как вертикальные/snap cards: `бумага` → `ДЭГ` → `итог`.
- **Зачем:** это самый «историйный» участок страницы. Таблица хороша для проверки, но плохо работает как TikTok/Reels-нарратив.
- **Как реализовать:** на desktop оставить таблицу, на mobile заменить на `.deg-card-list` с `scroll-snap` или вертикальными карточками. Каждая карточка: округ, кандидат до ДЭГ, стрелка, победитель после ДЭГ, отрыв. Объём: **M**.
- **Эффект / усилие:** 4 / 3.

## 8. Улучшить тактильность калькулятора

- **Что:** сделать range controls более физичными: 22-24px thumb на touch, заполненный track до thumb, live-подсветка изменившегося total, явный warning для недоопределённых сценариев.
- **Зачем:** калькулятор — главный интерактив. Сейчас он функционален, но ощущается как обычная форма; для вовлечения нужен ясный feedback на drag.
- **Как реализовать:** CSS custom property `--value` для track fill, `input` listener обновляет; `.calc-output-total.is-changing` коротко подсвечивает число; no bounce при reduced-motion. Объём: **S**.
- **Эффект / усилие:** 3 / 2.

## 9. Сделать heatmap mobile-first summary перед scroll-x

- **Что:** перед горизонтальной heatmap показать компактный вывод: `при 30% списка нужно ~75 округов`, затем саму таблицу с gradient scroll hint и sticky первой колонкой.

# III. ТЕХ-ДОЛГ

- `Chart.js` используется только для трёх простых bar charts (`years`, `opposition`, `shpilkin`). Стоит переписать на SVG и убрать CDN-зависимость: меньше веса, лучше offline/архивируемость, меньше риска при публикации.
- В HTML много inline styles: `rg` нашёл 114 `style="..."`. Это уже мешает системно править mobile/темы/print. Чистить постепенно, начиная с repeated heading/card/callout styles.
- `home.css` и `elections.css` дублируют паттерны hero, stats strip, cards, callouts. Имеет смысл вынести `stats-strip`, `callout-result`, `section-heading`, `mini-card` в components/layout.
- `assets/js/data/laws.js` можно оставить inline: 48KB для статического сайта не проблема. JSON имеет смысл только если данные будут валидироваться/генерироваться отдельным скриптом.
- `research/vybory-mathematics-research.md` содержит старые F1/F3 формулировки (`329`, `+14`, `10,92%`). Если этот файл будет публичным источником, его нужно обновить или явно пометить как архив до исправлений.
- Добавить маленький `tests/` или `research/checks/` JS-скрипт для `distributeHareNiemeyer`: official 2021, all parties, empty, all zero, one-positive invalid, loyalists cap.
- Modal/intro/spoiler a11y лучше централизовать через один helper для `inert`/focus restore, чтобы следующие интерактивы не копировали неполный паттерн.
